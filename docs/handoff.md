## 0. 한 줄 요약

2017-01 ~ 2026-10 서울 아파트 매매 실거래 617,592건으로 시장 국면(상승·조정·하락·회복)을 나눈다.
국면마다 각 아파트(단지×면적 = 셀)가 서울 평균보다 몇 %p 더/덜 움직였는지(y)를 아파트 특성으로 예측하는 회귀 모델을 만든다.
처음 보는 동네에서도 기준선보다 잘 맞히는 모델만 해석해서, 특성을 **전천후형·방어형·공격형·취약형·국면 무관**으로 구분한다.

- 예측하지 않는 것: 시장 전체 방향, 절대 가격
- 결과는 연관 관계다. 인과로 쓰지 않는다. 예: "역이 가까우면 버틴다"가 아니라 "역이 가까운 단지가 버텼다".

## 3. 국면 (확정)

**판정 규칙** (`src/regime/turning_points.py`, 2017~2019 데이터를 넣기 전에 고정함)
1. 3개월 중심 이동평균으로 평활
2. 앞뒤 6개월 안의 최고·최저 달을 정점·저점 후보로 잡음
3. 국면 최소 6개월, 순환 최소 15개월
4. 정점→저점 하락이 10% 이상이면 하락기, 3~10%면 조정기
5. 저점 이후 낙폭의 50%를 회복할 때까지 회복기

| 국면 | 기간 | 시작 기준월 a | 끝 기준월 b | 길이 L(개월) | 공식 실거래지수 변화 |
|---|---|---|---|---:|---:|
| 상승기 ① | 2017-01 ~ 2018-10 | 2017-01 (자료 시작) | 2018-10 | 21 | +34.7% |
| 조정기 | 2018-11 ~ 2019-04 | 2018-10 | 2019-04 | 6 | −5.1% |
| 상승기 ② | 2019-05 ~ 2021-10 | 2019-04 | 2021-10 | 30 | +64.1% |
| 하락기 | 2021-11 ~ 2023-01 | 2021-10 | 2023-01 | 15 | −23.6% |
| 회복기 | 2023-02 ~ 2024-07 | 2023-01 | 2024-07 | 18 | +14.7% |
| 상승기 ③ | 2024-08 ~ 진행 중 | 2024-07 | 2026-08 (공식 지수 마지막 달) | 25 | +24.2% |

**주의**
- 2019-05~06의 2개월짜리 회복기는 상승기 ②에 합쳤다.
- 조정기는 길이가 규칙 경계(5~6개월)에 걸려 있다. 공식 지수는 2019-03과 2019-04 값이 같다. 그래서 **포함·제외 두 경우를 모두 보고**한다.
- 조사 기반 지수(주택가격동향조사)는 3~4개월 늦고 폭이 절반이라 경계 판정에 쓰지 않는다.
- 2026년 하반기는 금리 인상(2026-07·08) 이후 지수가 정체 중이다. 새 국면 여부는 아직 판단할 수 없다.

## 4. 목표 변수 y (셀×국면)

모든 값은 로그 차이 ×100, 단위는 %p다. y > 0이면 하락기에는 서울보다 덜 떨어졌고, 상승기에는 더 올랐다는 뜻이다.

### 4-1. 창 방식 (주 분석)

1. 시작 창 = a ±3개월, 끝 창 = b ±3개월
   - 조정기만 ±2개월(±3이면 2019-01에서 겹침)
   - 상승기 ①의 시작 창은 2017-01~04
   - 상승기 ③의 끝 창은 2026-05~10
2. 창 안의 거래마다 시점 보정한 로그 가격을 구한다.
   `adj = ln(거래금액_만원 / 전용면적) − ln I[거래월] + ln I[a 또는 b]` (I = 자체 지수 `main`)
3. 셀의 시작 가격 = 시작 창 adj의 중앙값, 끝 가격 = 끝 창 adj의 중앙값
4. `y = (끝 − 시작) − (ln I[b] − ln I[a])`, ×100
5. 양쪽 창에 모두 거래가 있는 셀만 쓴다.
6. 가중치 w = min(시작 창 거래 수, 끝 창 거래 수)

### 4-2. 기울기 방식 (표본 확장·강건성)

1. 국면 기간 [a − k, b + k] 안의 셀 거래를 모두 쓴다(k = 3, 조정기는 2).
2. 각 거래를 서울 대비 상대 가격으로 바꾼다. `z = (ln 거래가 − ln I[거래월]) × 100`
   - 층 보정을 넣을 경우 이 단계에서 한다.
3. z를 경과 개월에 대해 직선 회귀해 기울기 s(%p/월)를 구한다.
4. `y = s × L`
5. 조건: 국면 안 거래 2건 이상, 첫 거래와 끝 거래 간격 6개월 이상
6. 가중치는 거래 수와 간격에 비례해 준다.
7. 가정: 셀의 상대적 강세(약세)가 국면 동안 대체로 일정하다. 창 방식과 결론이 같은지 반드시 비교한다.

### 4-3. 표본 수 (실제 계산값)

| 국면 | 창 방식 셀 | 기울기 방식 셀 |
|---|---:|---:|
| 상승기 ① | 5,950 | 10,538 |
| 조정기(±2) | 4,630 | 4,456 |
| 상승기 ② | 4,460 | 11,820 |
| 하락기 | 2,883 | 4,359 |
| 회복기 | 3,483 | 6,556 |
| 상승기 ③ | 5,660 | 10,206 |
| 합계 | 27,066 | 47,935 |

창 방식은 거래 161,703건(26.2%)을 직접 쓴다.

|---|---|---|
| 토지거래허가구역 | a월 말일 기준 지정 여부. `data/features/tohuh_regime_start_by_complex.csv` 사용 | 하락기·회복기·상승기③ 시작 시점에만 1이 있음(행 기준 355단지) |
| 가격대 | a−12 ~ a−4개월 거래의 셀 중앙 가격으로 9억 이하 / 9~15억 / 15억 초과 | 시작 창과 겹치면 안 됨(평균회귀 착시) |
| 직전 국면 y | 직전 국면의 y. 이번 국면 시작 창과 겹치지 않는 구간으로 계산 | 되돌림 통제 |
| 회전율 | 시작 창 이전 12개월 거래 수 ÷ 세대수 | 하락기 표본 쏠림과 얽힘 |

가격에서 나온 변수는 특성 효과를 흡수한다. 그래서 기본 feature에는 넣지 않고, 확장 모델에서만 넣어 "넣어도 특성 효과가 유지되는가"를 본다.

## 6. 분할·모델·평가

### 6-1. 분할
- 법정동(자치구+법정동) 목록을 고정 시드로 섞어 20%를 **최종 test**로 둔다. 모든 국면에서 같은 동을 쓰고, 이 목록은 파일로 저장한다.
- 나머지 80% 안에서 법정동 단위 5-fold `GroupKFold`로 하이퍼파라미터와 모델을 고른다. 고른 값으로 80% 전체에 다시 학습한다.
- test는 마지막에 **한 번만** 평가한다.

### 6-2. 모델 (국면마다 따로)

| 모델 | 내용 |
|---|---|
| 기준선 1 | ŷ = 0 (서울과 같이 움직였다고 봄) |
| 기준선 2 | ŷ = 학습 데이터의 자치구 가중평균 y |
| Ridge | 숫자는 표준화, 범주는 원-핫. 규제 강도는 CV로 선택 |
| 랜덤포레스트 | 나무 수·깊이·min_samples_leaf를 CV로 선택 |
| CatBoost | 자치구·난방·복도는 범주형, 결측은 그대로. 깊이·학습률·반복수는 CV(early stopping)로 선택 |

- 모든 모델에 가중치 w를 `sample_weight`로 준다.

### 6-3. 지표 (test, 가중)
- RMSE·MAE(%p)
- Spearman 순위상관
- 상·하위 20% 차이: ŷ 상위 20% 셀의 실제 y 평균 − 하위 20% 셀의 실제 y 평균
- 불확실성은 **단지 단위 부트스트랩** 95% 구간(1,000회)으로 낸다.

### 6-4. 특성 효과와 유형
1. **Ridge 표준화 계수**: 단지 단위 부트스트랩으로 95% 구간을 구한다.
2. **CatBoost SHAP**: 평균 효과의 부호와 의존도 곡선(예: 역 거리 몇 m부터 불리해지나)을 본다.
3. **효과 판정**: 두 방법의 부호가 같고 구간이 0을 포함하지 않으면 +/−, 아니면 0이다.
4. **위치 vs 건물**: 기준선 2와 전체 모델의 test 성능 차이로 설명 몫을 나눈다.
5. **유형 판정(사전 고정)**
   - 하락 효과 = 하락기(+조정기) 판정
   - 상승 효과 = 상승기 ①②③ 중 2개 이상 부호 일치

| 유형 | 하락 효과 | 상승 효과 |
|---|---|---|
| 전천후형 | + | + |
| 방어형 | + | 0 또는 − |
| 공격형 | − | + |
| 취약형 | − | − |
| 국면 무관 | 0 | 0 |

### 6-5. 보조 분석
- **국면 간 예측**: 앞 국면으로 학습해 같은 유형의 다음 국면을 평가한다(상승①→②, ②→③, 조정→하락). 하락 쪽 사례가 하나뿐이라 사례로만 보고한다.
- **강건성**
  - 창 ±2·±4개월
  - 기울기 방식 vs 창 방식
  - 셀당 거래 2건 이상만
  - 조정기 포함·제외
  - 단지 대표점 좌표만
  - 2020년 이후만(2017~2019에는 해제 표시가 없음)

## 9. 알려진 한계

- 하락 쪽 국면이 하락기 1개와 짧은 조정기 1개뿐이다. "모든 하락기에 통한다"고 주장할 수 없다.
  - 2006년부터 늘리면 하락 국면이 4개가 된다(2008, 2009~10 조정, 2011~13, 2021~23). 원자료를 추가로 받아야 한다.
  - 공식 지수는 이미 `rone_apt_trade_index_seoul_2006_2026.csv`에 있다.
- 단지 내부값(세대수·주차·난방·복도·시공사)은 현재값을 과거 전체에 적용한 가정이다.
- 재건축 진행, 학군, 조망처럼 관측하지 못한 변수가 있다. 강남·고가·대단지·신축은 서로 겹친다.
- 2017~2019 원자료에는 거래 해제 표시가 없다.
- 하락기(특히 2022년)는 거래가 적다. 양쪽 창에 거래가 있는 셀만 남아 표본이 쏠릴 수 있으므로 남은 셀의 구성을 함께 보고한다.
- 동(호수 정보) 컬럼은 2022년 이전 계약분이 미공개라 68.7%가 결측이다. 쓰지 않는다.

## 10. 지켜야 할 원칙

1. 거래는 지우지 않는다. 표본에서 뺄 때는 이유를 기록한다.
2. 피처는 그 시점(계약일 또는 국면 시작 월 a)에 알 수 있던 정보만 쓴다. 예: 개통 전 역, 개교 전 학교 제외.
3. y를 만든 거래와 같은 창의 가격 정보는 feature로 쓰지 않는다.
4. 결측은 임의로 0이나 평균으로 채우지 않는다. 모델 입력에서 대체할 때는 학습 fold 안의 통계만 쓰고, 결측 표시 변수를 남긴다.
5. 하이퍼파라미터·모델 선택은 80% 학습 구간 안에서만 한다. test는 한 번만 본다.
6. 실제로 계산한 숫자만 보고한다. 원본 파일은 덮어쓰지 않고 버전을 올려 저장한다.
7. API 키는 코드·채팅에 넣지 않고 환경변수로만 쓴다.

## 11. 생성형 AI에게 붙여 넣을 작업 지시문

```
너는 우리 팀의 머신러닝 연구를 이어서 진행한다. 저장소의 docs/handoff.md를 먼저 끝까지 읽고 §1의 결정과 §10의 원칙을 지켜라.

데이터: data/final/아파트_실거래_전처리_2017_2026_v5.csv.xz(UTF-8-SIG, 617,592행 × 43열, 열 설명 docs/data.md)와 data/regime/seoul_index_2017_2026.csv(main 열 = 서울 월별 지수). 규칙 값은 config/*.yaml을 읽어서 쓰고 코드에 다시 적지 않는다.

할 일(순서대로, 단계마다 결과 숫자를 표로 보고하고 다음 단계로 넘어가기 전에 확인받을 것):
1. 셀×국면 분석표를 만든다. 셀 = 자치구+법정동+번지+단지명 × round(전용면적). 국면과 기준월 a·b는 §3 표, y는 §4의 창 방식과 기울기 방식을 둘 다, feature는 §5-1(국면 시작 월 a 기준으로 다시 계산), 가중치와 제외 규칙은 §4를 따른다. 국면별 셀 수가 §4-3 표와 거의 같은지 확인한다.
2. 법정동 단위로 20% test를 고정 시드로 뽑아 저장하고, 80%에서 5-fold GroupKFold를 만든다.
3. 국면마다 기준선 1·2, Ridge, 랜덤포레스트, CatBoost를 같은 X·분할·가중치로 학습하고, §6-3 지표를 test에서 한 번만 계산한다(단지 단위 부트스트랩 95% 구간 포함).
4. 기준선 2를 이긴 모델에 대해 Ridge 계수 구간과 SHAP를 구하고, §6-4 규칙으로 국면별 효과와 특성 유형표를 만든다.
5. §5-2 통제 변수를 넣은 확장 모델과 §6-5 강건성 점검을 한다.
산출물: 코드는 src/cells·src/model·src/evaluate·src/report에, 확정 표·그림은 reports/final/cells·models·types·figures에 둔다. 새 테스트는 tests/에 추가한다. 원본 파일은 수정하지 말 것. 확정 결과를 바꾸면 python tools/verify_final.py --update로 해시를 다시 기록한다.
```
